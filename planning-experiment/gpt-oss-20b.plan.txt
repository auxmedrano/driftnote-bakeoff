**4. ACCORDION BEHAVIOR**

1. **Markup** – Each FAQ item is a `<button>` (trigger) followed by a `<div>` (panel).  
2. **Initial State** – All panels hidden (`height: 0; overflow: hidden;`).  
3. **Click Logic**  
   - When a trigger is clicked:  
     - If its panel is already open, collapse it (set `height: 0`, remove `aria-expanded="true"`).  
     - If it’s closed:  
       - Collapse any currently open panel (set its height to 0, update `aria-expanded`).  
       - Expand the clicked panel (calculate scrollHeight, set `height` to that value, set `aria-expanded="true"`).  
4. **ARIA** – Each button has `aria-controls="panel-id"` and `aria-expanded="false/true"`. The panel has `id="panel-id"` and `role="region"`.  
5. **Only One Open** – The script always queries for any button with `aria-expanded="true"`; if found, it collapses it before expanding the new one. No two panels can be open simultaneously.

**5. ACCESSIBILITY CHECKLIST**

| Element | aria‑attribute(s) | Purpose |
|---------|-------------------|---------|
| **Hamburger Toggle** | `aria-label="Open navigation menu"` (when closed), `aria-label="Close navigation menu"` (when open), `aria-expanded="false/true"`, `aria-controls="main-nav"` | Indicates state and controls the nav region. |
| **Navigation Links** | None required beyond native `<a>` tags. |
| **Accordion Trigger** | `aria-expanded`, `aria-controls` | Signals state and linkage to panel. |
| **Accordion Panel** | `role="region"`, `aria-labelledby` (link back to trigger) | Provides a labeled region for assistive tech. |

**Keyboard Operability**

- **Menu Toggle** – Focusable `<button>`; toggles nav with Space/Enter. When opened, focus is trapped within the nav until closed.  
- **Accordion** – Each trigger is a `<button>`; can be focused via Tab/Shift‑Tab. Space or Enter toggles expansion following the behavior above. Arrow keys can optionally move focus between triggers (optional enhancement).  

All interactive elements use native semantics (`<button>`, `<nav>`, `<header>`, `<section>`, `<footer>`), ensuring screen readers announce them correctly. Color contrasts meet WCAG AA for both light and dark themes.
