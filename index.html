Local model comparison

Four local models, one brief, one GPU.

Qwen3.8-27B, gpt-oss:20b, and two Gemma4 variants were each given an identical prompt — build a self-contained landing page for a fictional note app called Driftnote — and run independently via direct Ollama CLI calls on the same 16GB card. No edits, no retries. What follows is what each one actually shipped.

Does more planning help?

Follow-up experiment: each model re-run under two different kinds of "planning" — internal reasoning (think=high) versus an explicit two-step workflow where the model writes a design plan first, then builds from it — scored against a fixed 23-item checklist against the original brief.

5.5×

For gpt-oss:20b, writing an explicit plan first reached the exact same perfect score as heavy internal reasoning — at 5.5× less wall-clock time (49s vs. 4m 27s) and 5.7× fewer tokens.

More planning only helps where there's a gap to close. qwen3.8-27b-q3 and gemma4:12b already scored 23/23 at baseline — neither condition could improve on a perfect score, and extra planning showed up as breakpoint depth instead, inconsistently (qwen gained depth under reasoning; gemma4:12b's breakpoint count actually dropped under reasoning, 3→2). Only the two models with a real baseline gap (gpt-oss:20b, gemma4:latest) show a clean, unambiguous "planning helped" result — and for gpt-oss, the cheap kind of planning (writing it down) worked exactly as well as the expensive kind (thinking harder).

This checklist went through four rounds of fixes after manual verification caught real false negatives in the scoring script itself — worth knowing before trusting these numbers at face value.
